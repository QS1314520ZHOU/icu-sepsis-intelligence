## iframe专项已实测
- 真实不同来源 localhost ↔ 127.0.0.1 的父/子页面握手与后端取数，不是同页CSS伪装iframe。
- 子应用没有第二套全局顶栏、侧边菜单、患者列表或独立登录；只有当前患者核对条和四个局部页签。
- origin / source / channel不匹配的消息不能改变上下文；同一code不能重放，channel不匹配拒绝。
- 后端患者+住院范围令牌不能查询别的患者；患者列表即使直接请求也只能见授权患者；护士令牌不能提升为医生权限。
- 新上下文撤销旧通道令牌、主动revoke及过期后401；CSP允许明确宿主并移除冲突的全局X-Frame-Options DENY。
- 切患者会清除旧曲线、来源弹层及页面；故意延迟旧患者响应后，新患者不会被旧响应覆盖。
- 有未保存复核草稿时拒绝切换，宿主保持原选中态；保存/取消后才能继续。
- 子应用的证据、筛查、预警、任务操作保持在iframe内；清空上下文不遗留曲线，重载重新产生通道并握手。
- 650px宿主模拟与子应用均无横向页面溢出；数据表允许在自己的容器内滚动。

## 必须保留的限制
1. 本机host-demo不是医院宿主。未读取或导入宿主截图中的患者信息，仍只使用MOCK_ONLY模拟患者。
2. DEMO_MODE专用发行器是软件联调样例，不是医院SSO。真实身份交换、逐患者动态授权、patientId/encounterId映射、网关/TLS/CSP、正式消息字段适配仍需现场实现并审核。
3. 内存code/token仅用于单实例演示；未完成生产令牌存储、限速、集中撤销、登录与读取全量审计、多实例/HA、渗透或正式可用性研究。
4. 保留0.2全部临床边界：无真实预测模型、无风险百分比、完整SOFA未实现、正式治疗Bundle未启用，不能自动确诊或开医嘱。
5. Java15/Boot2.7老旧栈维护和后端漏洞评估仍未完成。Docker、真实医院部署、长稳/高并发/灾备未验证。
