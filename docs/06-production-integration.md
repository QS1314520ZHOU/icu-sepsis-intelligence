# 真实 ICU 接入与生产前检查

## 必须由现场补齐的信息
1. 宿主Java15工程及pom、Spring/Security/Mongo驱动版本、部署OS/CPU。
2. 实际Angular/AngularJS版本、路由、菜单、患者选择、页签和设计组件；两参考仓库的Vue不能证明宿主版本。
3. 真实宿主UI原文件及工作站分辨率；已收到本演示工作台截图，尚无医院宿主组件规范，不声称像素级一致。
4. MongoDB实际服务端版本、拓扑、认证/读写权限、只读源库集合、事件时间/入库时间字段、住院与设备绑定规则；不应在聊天中发送生产密码。
5. 临床授权人批准的规则、适用性、时间窗、Bundle指南版本和本地变体。
6. 合法脱敏历史数据及真实模型包；未提供前只能做模拟软件验证。

## 推荐接入顺序
- 源数据只读适配：独立账号、最小字段、参数/单位映射、住院与绑定时间校验；先离线脱敏样本契约测试。
- 新业务独立Mongo库/集合；事务、并发和索引先在匹配生产版本的隔离环境测试。
- SSO采用后端验证的签名令牌/会话适配，不相信前端传入角色/科室；细化科室及患者授权。当前开发账号只有同一授权科室范围，不支持患者级动态授权列表。
- 替换演示外壳，复用宿主导航/页签/患者上下文；不得在医院系统里嵌套第二套全局导航。
- 扩展完整临床规则、可靠异步扫描、任务重试/超时/进度/死信、规则审批及回滚。
- 回顾性验证→前瞻静默→临床复核→正式批准，不能从本次Mock演示直接上线。

## 安全与运维限制
当前HTTP Basic仅本机开发：角色密码>=16位且互异、BCrypt、后端RBAC、科室范围、输入校验、traceId、统一错误、业务审计；不把本次随机密码放进交付包。

**不是生产认证方案**：尚无SSO、MFA、登录限速、逐患者授权、组织隔离管理、登录/读取全量审计、CSRF生产策略和集中撤权。CSRF当前为无Cookie/显式Authorization的开发方式关闭，跨站策略需结合最终认证重新评估。生产必须TLS、可信反向代理、网络隔离、最小权限账户、审计不可改存储、集中密钥管理、依赖漏洞复核与补丁渠道。Java15和Boot2.7维护风险不能以“兼容”代替安全评估。

MongoDB要求副本集；开发无认证仅绑定localhost，不可直接复制到生产。事务冲突返回409，数据源不可用503；当前不提供HA部署、灾备或可靠重试保障。审计在应用层不可改，不等于数据库管理员不能篡改，应使用分离职责、只追加角色及归档签名。

Docker文件只提供开发模板，本环境无Docker，未构建运行验证。镜像tag/CPU架构/供应链完整性需部署前校验。真实临床数据切勿进入本演示库、日志、截图或外部AI服务。

## 0.2 可视化接入注意
患者摘要目前为有上限的逐患者查询，展示20条分页，不是大科室压测通过的聚合服务。生产接入应改为批量聚合/读模型，保留住院、科室与事件/入库时间双重约束。趋势服务仍限定24小时最多2000条，达到上限显示不完整提示；未实现长时间窗的分桶、分页与服务端降采样。
