## 空 BQDM 修正

进一步核对确认附件请求 BQDM=""，响应文书的 BQDM 则不全为空。因此修正此前适配代码的非空限制：明确配置为空时不作为响应科室过滤器，仍逐文书严格核对 BLH。非空 BQDM 时仍逐文书要求一致。即使 BQDM 为空，也不能绕过宿主患者/住院/当前科室核验。空过滤值并不代表完整性已确认，complete 仍未知。

此项说明替代 docs/33 中“每份响应 BQDM 必须与请求一致”的笼统描述：该规则只适用于非空 BQDM 过滤器。

## 多科室

前台沿用 host-context 桥接：postMessage 提供患者上下文，服务端从医院只读源核实患者、住院及科室后建立 grant，不能直接信任任意消息内的科室字符串。Store 的嵌入请求范围优先用 grant.department，而不是 app.department。

app.department 保留为非嵌入访问及部分既有后台功能的回退值，不是将全部 iframe 绑定到该科室。不能简单删掉或改成全科室权限。其他既有定时任务的独立扫描策略不因本批配置自动变成全院扫描。

新增 app.clinical-notes.scan-known-departments：开启时病程补偿任务从项目已有患者上下文提取科室，分别检查在科名单并按全局人数上限轮转；每个患者仍重新核验源住院和源科室。不因固定默认科室而漏掉另一已建立上下文的科室。未建立本地上下文的患者仍不在扫描集合内，不宣称全院文书已同步。
