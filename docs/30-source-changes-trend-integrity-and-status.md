# 剩余任务核查与本轮开发验证

日期：2026-11-06。承接 docs/29。本记录以具体能力及前置条件说明状态，撤回先前无可复核权重的 75%–80% 粗估；测试通过不等于整个交接计划完成或获准临床使用。

## 本轮实际改动

1. 修正 AI 结构化趋势整理（PatientContextBuilder）：在整理函数内再次限制近 24h、排除非有限数值及未来已知取得时间；单位缺失/不同或同一时刻不同值明确不合并。相同时间相同值去重，防止重复数据增加次数。保留血压分通道，不自行换算单位或选优。同类同单位并不保证不同来源已经医学可比，此限制仍须来源核实。
2. 停止根据未确认的尿量间隔/累计含义直接累加 6h/24h 总量，改为明确的数据限制提示。不改 ICU-05 补液判定或其他规则。取得时间未知的既有数据不被此功能宣称为已通过回顾性冻结；当前趋势描述不等于可用于历史预测训练。
3. 增加内部 SourceChangeDispatcher 契约，限定医嘱、用药执行、液体执行、检验、生命体征及病程变更类型。重新核验当前授权患者/住院/科室；按来源+患者住院+事件标识识别重复；同标识内容冲突拒绝，已知未来来源时间拒绝；迟到/乱序仍失效对应缓存，不覆盖数据或推进临床时间。
4. 通知本地 ICU-05 看板和预警评估缓存失效，后续原有请求/定时补偿重读来源。通知不自动执行医嘱、不关闭预警、不写临床数据。未新增事件接收 HTTP 路径或猜测医院协议。去重只在单进程内保留最近 1024 项，重启/淘汰后允许再次失效；不是持久化事件队列或精确一次保障。发布失败不记为已送达，可补偿重试，已完成的缓存失效可安全重复。真实接收端、多实例、持久化与来源补偿仍待真实协议设计。
5. ICU-05 汇总/文本报告增加未达标原因：仅纳入分母且窗口状态明确未达标，按窗口/原因/患者住院去重；同病例可有多原因，不将原因数相加当分母。未知与进行中不变为失败。不改原窗口率、T0 或候选条件。
6. 修正患者/生成内容切换后，旧 AI 反馈请求失败或结束状态污染新内容的问题；质控报告组件卸载后丢弃异步结果和旧复制提示。

## 必须提供的外部前置

1. K1 窗口起止及 V3 继承冲突：当前始终“无法判定”，页面“乳酸取值窗口待确认”。选最高值已确认，但不据此猜窗口；不允许覆盖绕过，也不更改分子分母。
2. 病程 HTTP 协议、认证、请求/住院映射、标识作用域、分页/截断、文书类型、来源可用时间与版本排序样本。记录.txt 仍缺；不能据字段名猜测。
3. 真实补液/药物执行数据与分类、自动 SOFA 所需可靠基线/来源/版本、临床排序阈值及时间窗的批准规则。
4. 可靠来源变更/出科事件协议和权限；无事件时继续定时补偿，不能保证出科前最后文书完整。
5. 院内模型位置、允许的数据用途及最小化方案、授权和身份保护审批。当前有限正则不保证原文去标识化；未获保护的病历不向模型发送。
6. 转科/出科授权、长期保留制度、密钥与完整备份恢复、数据库/备份/传输加密的院内验收。
7. 有权使用的国内规范、科室 SOP 原文及负责人核实。不能自行编写并标注为医院已生效规范。
8. 临床评审参考标准及病例、风险研究终点/风险集/事件时点、标签与数据批准；没有这些不能完成可信研究建模或临床验收。

这些缺口限制完整功能实现及验证，尚不能声称全部开发完成。没有将审批事项伪装成已启用功能，也没有把测试替代临床验证。
