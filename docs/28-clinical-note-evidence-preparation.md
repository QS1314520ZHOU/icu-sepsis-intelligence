## 本批改动

1. 增加医生主动使用的病程证据准备接口 GET /api/v1/patients/{patientId}/clinical-notes/review-evidence。复核时点 asOf 默认为服务器当前时间，未来时点拒绝。重新核验患者、本次住院及科室权限；护士和质控角色不能使用该准备/片段接口，既有受控病程阅读权限独立保留。
2. 将文书记录时间和来源可用时间分开。来源明确确认的可用时间与本地取得时间均不得晚于复核时点；边界相等可进入核对。来源可用时间、文书类型、归属、版本排序含义均需显式确认。没有文书记录时间不会自动否定已经明确确认的来源可用时间。正文日期和本地抓取顺序不能代替来源可用时间或修订语义。
3. 每份文书分别处理版本。只在版本排序语义已确认时选择该时点可用的新版本；同时间的不同版本冲突保持未知，不凭导入顺序选择。不同文书分别保留。未知 eligible=null 与时间上不可用的证据排除分开；后者也不等于临床条件不满足。
4. 检查达到本地扫描上限时，整批所检查记录保持未知，不从不完整历史集合中选出看似正常的版本。当前源同步状态单独展示，historicalCoverageConfirmed 始终为 false；当前源完整不能证明过去时点完整。
5. 增加 POST /review-evidence/excerpt。仅对已通过核对的快照提供最多 1000 个 UTF-16 单元的连续精确片段，防止切开代理字符。请求只带快照、时点、范围和证据集合指纹；服务重新检查集合和授权，再从受控原文提取。集合变化时拒绝旧引用。响应包含来源、时间、范围和本地 N 编号；审计不保存片段正文。
6. 页面按需加载独立证据面板，显示可核对、未知、时点不符及扫描限制。医生在原文中选中文字后核对片段；前端再次检查患者、住院、快照、时点、集合指纹、范围及逐字内容。错误响应或切换患者清除旧结果；所有正文按文本显示。没有调用模型、生成诊断、写医嘱或正式病历。

## 长期快照与时间精度

新写入采用密文封装 v3，认证附加数据绑定患者/住院/科室、来源标识、文书类型、时间、确认标志、精度和冲突状态等元数据。读取兼容旧 v1、v2；旧 v1 的时间元数据未认证，旧 v2 未记录精度保证，因此仍可在权限下读原文，但不自动进入已核对的历史证据。

同步在取得来源文书后记录本地取得时间。MongoDB 日期仅有毫秒精度，来源和本地取得时点均取毫秒上界，避免截断把亚毫秒之后的信息提前到过去；原始时点保留在加密载荷中。来源已知时间冲突单独标记。该时点只是取得/归档参考时间，不是精确数据库事务提交时刻，也不意味着已通过回顾性研究方法验证。

病程目录先读无密文、nonce 和密钥标识的元数据；证据准备按限定集合流式读取密文，小批量逐条校验真实性和正文结构，不在返回包中保存全文或密文。游标用完或失败均关闭；数据库读取失败不能返回正常空结论。新增患者/住院/科室与取得时间、ID 的复合分页索引。没有 TTL 或自动删除；病程独立密钥与 AI_STORE_PROMPT=false 的默认隐私策略继续保留。

## 剩余优先级与边界

1. P1 待现场确认：K1 的选值方式保留为有效窗口最高乳酸、阈值 ≥2 mmol/L，但窗口未确认前始终“无法判定”，页面显示“乳酸取值窗口待确认”，不允许人工覆盖绕开。未改变 ICU-05 T0、分子、分母。真实补液执行量/单位、感染部位来源和自动 SOFA 数据映射及同版本评分仍待核实。
2. 病程只读接入：记录.txt 样本仍缺；HTTP 方法、认证、BLH/BQDM/本次住院映射、标识作用域、分页/截断、时间及版本含义须现场确认。尚无实际医院 HTTP 适配器，源同步默认关闭。转科/出科授权、可靠事件与最后同步、限流、保留年限、密钥和全库备份恢复仍待验收。
3. P4 可继续本地开发：证据支持关系、否定/既往/引用复制/相反证据及其他病因的处理、完整中文复核草稿与本地质控报告。此次只是时间版本准备和原文定位，没有实现医学语义核验。实际病程模型调用须先确认院内部署/审批、最小必要片段及保护方式；本地片段没有宣称已完成身份信息清除。不能借综合复核修改规则或自动关闭预警。
4. P2/P3：完整临床排序输入、可靠新事件流和执行关联、AI 采纳修改与工作量统计、可靠临床事件提前量仍待完成，当前基础队列和反馈率不能替代。
