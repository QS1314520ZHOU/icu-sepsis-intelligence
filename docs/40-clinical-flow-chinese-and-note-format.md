1. /14 是当前五项 MEWS 的满分，不是 14 个步骤。界面改成“5分”“待补全”或“不适用”；满分和阈值只在评分规则中解释。
2. MEWS 来源直接显示“观察项”，源字段和记录编号仅在“技术追溯”中按需展开；原始数值、时间和追溯信息保留。
3. 顶部新增可点击的“早期筛查 → 床旁复评 → 感染/器官核对 → Bundle执行核对”导航，标出当前重点。有异常时优先床旁复评，不要求先凑完整评分。各步不代表已执行或已诊断，不自动开医嘱；它是对现有记录和操作入口的组织，不是已联通院内抢救协议。
4. K1 仍无法判定。将主卡片矛盾的“未达条件”文案改为“资格待确认”，候选窗口长说明收进规则详情。人工排除、器官说明、培养明细和同步信息默认收起。超过六小时的 T0 标为历史记录，不把数百小时前的措施当作当前待办。
5. AI 输入中的 MEWS 状态先变成中文，生成提示要求简体中文；已缓存回答和复制文本中的已知内部枚举也作中文展示，MEWS/qSOFA/AVPU 等必要缩写不替换。原始引用和数值不变。

## 成人适用性修复

截图中“成人适用性未确认”不只是排版问题：生日字段有意不落本地患者上下文，但真实评估使用本地上下文后没有重新读取。

现在仅在同一患者 ID、住院 ID、科室全部核验一致时，从源患者补取生日用于内存中的成人校验。来源不可用或归属不一致仍保持未知；未成年不套成人评分。生日不显示、不落业务患者集合；患者原对象不被写入生日。镇静、嗜睡等仍不猜测转换成 AVPU，缺项不计零。

## 病程失败的定位与受控兼容

现场截图显示：同步、适配器及密钥已就绪，失败发生在响应解析阶段，零份快照，所以 AI 无病程片段可读。

对用户此前提供的 记录.txt 做了只在内存中的离线解析：严格 JSON 首个错误为第 11 行第 40 列的未转义控制字符。仅处理裸换行后，又发现非法反斜杠转义。最终按受控方式规范 WBNR 正文转义后，175 份文书通过 JSON 结构、BLH 住院归属、数量和正文上限校验。没有连接医院接口、写入真实病程库或将真实正文发给模型；这不能证明现场最新响应已成功联通。

“引号多”不是原因：合法的反斜杠转义双引号和中文引号都支持。当前兼容范围严格限定为 WBNR 字符串中的裸 CR/LF/TAB，以及 JSON 不认识的反斜杠转义（保留为字面反斜杠）。不猜修裸双引号，不修改患者字段，不修补重复键或尾随对象，不跳过失败归属；错误 Unicode 和无法解释的结构仍拒绝。

新增开关：app.clinical-notes.blbcjl.allow-legacy-body-escaping / CLINICAL_NOTES_BLBCJL_ALLOW_LEGACY_BODY_ESCAPING。公开模板默认 false，交付现场配置为 true，以匹配已提供响应的格式。正常 JSON 优先严格解析；仅严格语法解析失败且开关开启时尝试上述兼容，之后再次严格解析和核验。长期应由源接口采用 JSON 序列化器正确输出。

兼容处理的标记随快照正文一起加密保存，查询原文时可查看；没有修改既有加密版本、密钥或 AAD 规则，不影响旧快照解密。同步结果仍不宣称源完整性已确认。

错误提示现在区分 JSON 语法/转义不合法、JSON 合法但字段结构不符、归属失败、网络或 HTTP 错误及密钥问题。病程 AI 未取到片段时显示相应安全原因，并可直接打开当前患者病程同步详情。修复了该入口在患者住院信息异步补齐时自动折叠、丢弃加载结果的问题。

本地片段草稿已更名为“所选片段草稿（本地）”，仅在有核验片段后出现。删除“AI 综合复核尚未启用”的旧全局文案，明确本地整理不调用模型，AI 片段复核由概览入口主动调用。没有把有限片段复核称为完整病程综合诊断。
