# 可视化设计与数据契约

目标：用患者表定位人，用趋势核查变化，用原始证据复核，用任务状态和数量图追踪工作，而不是装饰性大屏。

## 页面
1. 患者列表：床位 / 患者、当前有效 HR / MAP / 乳酸、时间、最新筛查、证据入口。异常筛查有文字和颜色双提示；未测/过期不显示为正常。
2. 患者页：首屏最近筛查摘要（明确非诊断）→六指标曲线→原始观测表与筛查证据→历史。历史选择明确标注“所选历史筛查”，不伪装最近一次。
3. 总览：实际授权患者快照与待处理预警/执行记录队列，最多20患者、每队列3条，数量以顶部后端统计为准。
4. 质控：同时间窗数量条形图与明细表，分母与排除口径可核对；不伪造多日趋势、准确率或模型校准图。

## 技术决策
这里是需要鉴权、后端取数、住院上下文、数据点证据跳转与写操作闭环的 Angular 应用组件，不是静态 Notion 图表附件。使用原生 Angular/SVG 分面折线，避免为了六条独立曲线增加图表运行依赖；几何、分段、范围、单位和冲突处理有纯函数测试，真实浏览器验证SVG坐标、窗口切换与来源一致性。独立只读HTML预览由真实运行DOM/SVG导出，所有内部操作禁用，仅预览页签可切换。

## 接口增量
- GET /api/v1/patients 现返回 vitals（HR/MAP/LACTATE 的已校验 observation）、latestAssessment、summaryAt、summaryLimitReached；保留既有分页及患者字段。
- GET /api/v1/patients/{id}/clinical-data 及兼容别名 trends 增加 asOf 与 windowStart；仍为24h、最多2000条的原始观测快照，不是服务端自动预测或聚合。
- 无新增临床写接口，无扩大角色权限。原医生/护士/质控职责保持。

## 色彩与交互
沿用所提供演示截图的蓝白结构。曲线颜色区分指标，不代表正常/异常分级；单位直接写在指标标题旁。粗值、清晰刻度、淡网格；无平滑、发光、3D、装饰雷达。宽屏三列、窄屏单列，宽表在容器内部滚动，患者列表证据入口保持可达。曲线旁提供核查按钮与完整原始数据表，不能只靠颜色或图像读取信息。
