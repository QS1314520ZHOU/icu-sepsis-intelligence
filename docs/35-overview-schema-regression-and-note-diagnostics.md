# 概览 ICU-05 版本兼容与来源记录显示回归修复

2026-11-06，承接 docs/34。用户反馈的是概览“血培养/广谱抗菌药/晶体液/血管活性药”清单显示未接入，以及乳酸已有候选值却主数值为横线。

## 确认的问题与修复

1. 后端 Icu05Service 的响应 schemaVersion 已为 3，前端 SepsisPanel 却仅接受 1。已返回的患者 ICU-05 结果因此被丢弃，概览误回退到旧清单。旧清单前三项文字写死为“未接入”。原合成浏览器固定 schemaVersion=1，因此未覆盖真实协议变化。
2. 新增明确支持版本判断，接受 1/2/3，未知版本仍拒绝，保留原患者/住院一致性校验。概览恢复使用后端已计算的 ICU-05 窗口、来源记录、执行/审核时间和详情；不将真实接口失败当作无记录。失败或上下文/版本不匹配有单独提示。
3. 浏览器合成 fixture 默认改为 3，ICU-05 场景另逐一验证 1/2/3 均显示真实返回的结果卡，不出现旧回退清单；检查抗菌药 +0:40、血培养 +0:50 的合成时间。此处为程序回归数据，不是实际医院病例。
4. 回退清单文案改为相应实际证据“待核对”，不凭固定文案断言源未接入；完整有效 ICU-05 结果可用时根本不显示该清单。血培养动作明确标注医嘱时间含义（服务端有审核/开立含义时沿用），不把审核时间当作已采血时间。
5. K1 窗口待确认或整体 unknown 时，非纳入卡片的措施记录默认展开；不再把未知文案说成“未达条件”。不会通过放宽 K1 或改变分子分母恢复显示。
6. 乳酸仅有 context_only 候选值时，主数值直接显示该报告值和原单位（缺单位明确标注）；旁边“报告值·待核对”，显示报告时间及“不参与自动判断”。不进入正常/异常着色、趋势或临床规则，不将获取到了与能参与判断混为一谈。标题由“缺”改为“待补充/核对”，已取得的乳酸报告明确列为待核对。

## 病程可诊断状态

ClinicalNoteService 目录增加三个布尔状态：同步开关、接口适配是否存在、快照密钥是否可用，不返回配置值。HTTP 客户端、严格解析和归属核验保留安全的固定失败类别，页面区分配置缺失、HTTP 非 200、响应类型、超限、网络失败、业务失败、JSON 不符合约定、归属不匹配和正文无效。失败不会删除旧快照或重置最后成功同步时间。

这不能证明病程接口已在内网成功。先前未联通真实接口，本次也没有访问医院；需要在内网“记录与依据→病程记录与长期快照”查看状态，不能凭页面空列表推断无病程。新回归验证“接口失败”状态可见且旧快照原文入口仍在。
