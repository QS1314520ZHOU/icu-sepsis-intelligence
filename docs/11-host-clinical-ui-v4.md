# 宿主风格界面修订 v4

## 本轮改了什么

这是 **v3 之上的前端增量修改**，不是再次交付 v2/v3，也不是临床决策功能已完成的声明。

- iframe 沿用宿主的蓝白视觉、细边框、紧凑表格与按钮；无第二份患者列表、登录或全局导航。截图中的顶部及左侧是测试宿主，不属于子页面。
- 五页统一：临床概览、观测趋势、原始记录、预警处置、执行与审核。
- 概览第一行突出当前状态、缺项、待复核和待审核；主区显示数值与曲线，右侧保留待办及异常来源；核对表紧随主区，不再被右栏高度撑出大段空白。
- 无数据不再用大段说明撑满页面。改为紧凑指标条、短状态、查看历史/原始记录操作；不画假曲线，不把缺数当正常。
- 工程说明、绘图方法、任务规则改为可展开查看。源不可用、候选报告不能参与判断、历史记录等关键状态仍明确展示。
- 原始记录支持指标筛选、实际时间窗筛选、最新/全部切换、来源抽屉；全部模式每页 30 条是 **已读取结果的客户端分页**，不是新实现的数据库分页。
- 预警列表及复核弹窗统一样式；当前患者范围内不反复展示内部患者 ID。原有原因必填、角色检查、保存和错误处理保持。

## 历史数据交互

- 概览维持 6/12/24 小时，空态“查看历史记录”进入独立趋势并请求近 7 天。
- 趋势支持 6/12/24/72/168/720 小时。超出已加载时间窗时真正调用现有 `clinical-data?hours=...`，不是只改按钮文字。
- 原始记录支持 12/24 小时、7/30 天；表内数据也按所选窗筛选，而不只是改变标签。
- 所有时间窗相对 API 的 `asOf`。历史记录明确标记，不能拼成当前状态。
- 未新增全库“最近一条”搜索。已有源端记录上限和数据质量限制依然存在；结果达到 2000 条时显示可能截断提示。不能把 30 天范围等同于完整 30 天病历。

## 没有改动的边界

- **没有修改任何 Java 后端逻辑、MongoDB 源库/索引/拓扑、宿主消息协议或身份认证。**
- v3 的有创/无创分通道、未知保持未知、乳酸候选不参与当前判断和曲线仍保留。
- 未接入外部 AI；没有生成风险概率、休克确诊、自动治疗达标或新的医嘱。
- 用户报告的 standalone Mongo 业务事务写阻塞不由本次界面修改解决；不宣称已完成真实业务写入验证。

## 给已有 main 的应用方式

用户报告本机 `main` 为 `f32c0e7`，已合入 v3；本环境无法直接验证该未推送提交。补丁基于相同 v3 源内容（本环境基线 `bda1112`），只包含前端、文档和测试。**不要覆盖整个本地项目，不要重新应用 v2/v3，不要 reset --hard。**

1. 先备份/提交本地改动，在已有 v3 的主线创建新分支。
2. `git apply --check /path/to/host-clinical-ui-v4.patch`。
3. 无冲突再 `git apply /path/to/host-clinical-ui-v4.patch`；有冲突就合并对应前端文件，不能整包覆盖。
4. 前端执行 `npm ci && npm test && npm run build`。按项目已有构建方式，将新的前端产物打入当前后端；也可在 Java 15/Maven 环境运行 `bash scripts/build.sh`。
5. 保持本机现有环境变量和源库配置；更新服务后，按原宿主 iframe 入口核对。静态资源文件名变化，浏览器应重新加载。

完整 ZIP 内 JAR 仅是本环境 v3 后端 + v4 前端的参考运行包，不包含用户本地未推送的其他改动，也不包含账号、密码或医院数据。已有本地修改优先应用增量补丁后自行构建。
