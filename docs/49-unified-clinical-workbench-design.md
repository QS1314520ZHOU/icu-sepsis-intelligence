# 2026-11-08 六工作区统一设计与预警语义

本记录替代47/48中关于概览主标题及配色的旧展示说明。主题保持医院蓝白，按临床任务组织，不引入新的诊断阈值。

## 问题与设计依据
旧顶部颜色来自最严重的单项观测，而标题来自独立计算，造成同句“资料不足”可红可黑；GCS2可把顶部染红，但它并不单独构成休克预警。先前把全段诊断放在标题也把背景信息误作当前结论。现在统一任务层级：风险/依据/下一步 → 当前观测 → 专项复核；背景与技术细节按需展开。

## 六页最终结构
| 页面 | 首要任务 | 内容与交互 |
|---|---|---|
| 概览 | 是否预警、为什么、下一步 | 顶部使用已有后端预警分类，直接展示状态与依据；医生复核按钮固定右侧，体征连续监测栏，MEWS分项折叠，感染/器官核对双列；源诊断默认折叠 |
| 组合趋势 | 判断体征、检验与用药的时序关系 | 时间范围/可得性/指标控制区、常用组合、共享时间轴及按需范围AI；保留宽屏、拖选、用药点和自定义密度 |
| 病程与依据 | 找到原文和可追溯依据 | 病程/观察项分视图，刷新/同步/片段AI明确；新增按文书类型查找本页病程，明示本页范围；原文侧向弹窗，连接诊断默认收起 |

| 科室质控 | 找出需要关注病例、检查时效 | 统计概况条、1h/3h/6h达标率与可判定病例数、过程指标、病例清单；口径与完整性细节默认折叠 |

## 预警语义与颜色
顶部采用SepsisAssessmentService新增currentWarnings，直接调用已有ScreeningAlertService.fromReview的纯分类函数，不复制另一套医学阈值，不创建或修改预警记录。
- 红：当前结构化证据触发既有suspected_shock分类；感染线索同时存在时显示“疑似脓毒性休克，立即床旁复评”，否则显示“休克风险预警，需核对感染证据”。均非确诊。
- 橙：infection_abnormal、MEWS触发或其他需复评异常；单独GCS异常不能把顶部标成红色休克预警。
- 灰：未触发或资料不足，以明确文字区分；没有数据不能显示正常/已排除。
- 指标数值保留各自异常程度着色，与顶部预警不是同一维度，图例明确为“顶部预警”。宿主回传也使用同一顶部等级与结论，避免内外状态冲突。
- 历史Bundle状态不覆盖当前预警标题，不把历史T0冒充当前休克；历史措施在Bundle页核对。已有待处理预警继续通过待处理入口访问。
